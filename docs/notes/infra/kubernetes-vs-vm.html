쿠버네티스 vs VM — 핵심 차이

두 기술 모두 "격리된 환경에서 앱을 실행"하는 목적은 같지만, 작동 방식이 근본적으로 다릅니다.

항목 VM (가상머신) 쿠버네티스 (컨테이너)
격리 수준하드웨어 수준 (강함)프로세스 수준 (가벼움)
부팅 시간수십 초 ~ 수 분수 초 이내
용량GB 단위 (OS 포함)MB 단위
OSVM마다 별도 OS호스트 OS 커널 공유
확장성수동 또는 느린 자동화자동 스케일링 (HPA)
이식성이미지가 무거움어디서나 동일 실행
보안 격리매우 강함VM보다 약함
실제로는 함께 사용
현실에서는 VM 위에서 쿠버네티스를 돌리는 경우가 대부분입니다. VM은 인프라 격리를, 쿠버네티스는 앱 배포 자동화를 담당합니다.
VM 위에서 쿠버네티스가 동작하는 전형적인 구조
2

클러스터를 요청하면 어디에 생성되는가

인프라팀에 클러스터 생성을 요청하면, 환경에 따라 클라우드(AWS EKS, GCP GKE 등) 또는 온프레미스(사내 물리 서버) 위에 생성됩니다.

인프라팀이 실제로 하는 작업
① 서버(VM 또는 물리) 할당 → ② OS 설치 → ③ 쿠버네티스 구성 (Master / Worker / Ingress 노드) → ④ 네트워크·스토리지 설정 → ⑤ kubeconfig 파일 전달

받게 되는 것은 kubeconfig 파일입니다. 이 파일을 ~/.kube/config에 넣으면 kubectl로 클러스터를 제어할 수 있습니다.

kubeconfig 예시
apiVersion: v1
clusters:
- cluster:
    server: https://10.0.1.10:6443   # 클러스터 API 주소
    certificate-authority-data: ...
  name: my-cluster
users:
- user:
    client-certificate-data: ...
    client-key-data: ...              # 인증 정보
contexts:
- context:
    cluster: my-cluster
    user: dev-team
하나의 물리 서버 위에 여러 클러스터가 공존하는 구조
3

Worker Node = VM 자체 (오해 바로잡기)

Worker Node가 VM 안에 또 다른 무언가가 생기는 것이라고 오해하기 쉽습니다. 하지만 Worker Node는 그 VM 자체에 붙는 역할 이름일 뿐입니다.

Worker Node는 새로운 장비가 아니라 VM에 붙는 역할 이름
💡
인프라팀이 VM을 만들고 → kubelet을 설치하고 → Control Plane에 등록하면 → 그 순간부터 그 VM의 이름이 "Worker Node"가 됩니다. 서버 안에 서버가 생기는 게 아닙니다.
4

전체 구조 — 물리 서버에서 클러스터까지

지금까지 배운 내용을 한 문장으로 정리하면:

물리 서버(고사양) → 하이퍼바이저가 VM을 여러 개 생성 → 인프라팀이 VM 일부를 묶어 쿠버네티스 클러스터로 구성 → kubeconfig를 팀에게 전달 → 팀은 kubectl로 클러스터 제어
물리 서버 → 하이퍼바이저 → VM → 클러스터 → kubeconfig → kubectl 전체 흐름
"클러스터 달라"는 요청 = "물리 서버 자원 중 일부를 VM으로 할당해서 쿠버네티스 환경 하나 만들어줘"와 동일한 말입니다.
5

클러스터 구성도 — Master / Ingress / Worker Node 역할

쿠버네티스 클러스터는 크게 세 종류의 노드로 구성됩니다. 각 노드는 역할이 명확히 분리되어 있어서, 두뇌(Master) · 문지기(Ingress) · 일꾼(Worker)으로 이해하면 쉽습니다.

Master Node
클러스터의 두뇌
· API Server — 모든 명령 진입점
· Scheduler — Pod 배치 결정
· etcd — 클러스터 상태 저장
· Controller Manager — 상태 유지
Ingress Node
클러스터의 문지기
· 외부 트래픽 최초 진입점
· URL 경로별 라우팅
· TLS/SSL 처리
· nginx / traefik 등 실행
Worker Node
클러스터의 일꾼
· 실제 앱 컨테이너(Pod) 실행
· kubelet — Master와 통신
· kube-proxy — 네트워크 처리
· Container Runtime (Docker 등)
쿠버네티스 클러스터 전체 구성도 — 노드별 역할과 트래픽 흐름
트래픽 흐름 요약
외부 요청 → Ingress Node(문지기, URL 라우팅) → Worker Node(실제 앱 실행)
개발자 명령 → Master Node(두뇌, 상태 관리) → Worker Node(Pod 생성/삭제)
