왜 Scanner가 아니라 BufferedReader인가

코딩 테스트에서 입력 데이터가 10만 줄 이상이면 Scanner로는 시간 초과가 납니다. BufferedReader는 내부 버퍼(8KB)에 데이터를 모아서 한 번에 읽기 때문에 Scanner보다 5~10배 빠릅니다.

Scanner는 정규식으로 파싱, BufferedReader는 버퍼 단위로 읽고 단순 분리
항목 Scanner BufferedReader + StringTokenizer
속도 느림 (정규식 매번 호출) 빠름 (버퍼 + 단순 split)
타입 변환 nextInt() 자동 변환 Integer.parseInt() 수동
구분자 공백, 줄바꿈 자동 readLine() 후 직접 토큰화
예외 처리 없음 IOException 필수
코테 결론 소규모 입력만 OK 항상 이걸 쓰자
2

BufferedReader + StringTokenizer 입력 패턴

BufferedReader는 한 줄씩 문자열로 읽고, StringTokenizer로 공백 기준 분리합니다. 이 두 개의 조합이 Java 코테 입력의 정석입니다.

패턴 1: 정수 한 개 읽기

Java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
int n = Integer.parseInt(br.readLine().trim());

패턴 2: 한 줄에 여러 정수 (공백 구분)

입력: 5 3 7

Java
StringTokenizer st = new StringTokenizer(br.readLine());
int a = Integer.parseInt(st.nextToken());
int b = Integer.parseInt(st.nextToken());
int c = Integer.parseInt(st.nextToken());

패턴 3: N줄에 걸친 2차원 배열 입력

입력 예시:
3 4 (N행 M열)
1 2 3 4
5 6 7 8
9 0 1 2

Java
StringTokenizer st = new StringTokenizer(br.readLine());
int N = Integer.parseInt(st.nextToken());
int M = Integer.parseInt(st.nextToken());
int[][] grid = new int[N][M];

for (int i = 0; i < N; i++) {
    st = new StringTokenizer(br.readLine());
    for (int j = 0; j < M; j++) {
        grid[i][j] = Integer.parseInt(st.nextToken());
    }
}

패턴 4: 공백 없이 붙어있는 숫자

입력: 10110 (각 자리가 0 또는 1)

Java
String line = br.readLine();
for (int j = 0; j < M; j++) {
    grid[i][j] = line.charAt(j) - '0';  // char → int 변환
}
StringTokenizer vs split()
• split(" ")은 내부적으로 정규식을 사용해서 상대적으로 느림
• StringTokenizer는 단순 문자열 분리라 약 2배 빠름
• 코테에서는 항상 StringTokenizer 사용 권장
💡
자주 하는 실수
• readLine().trim() — 끝에 공백/개행이 붙어 parseInt가 실패하는 경우 방지
• st를 매 줄마다 새로 생성 — 한 번 만든 st를 다음 줄에 재활용하면 안 됨
• nextInt() 뒤에 nextLine() — Scanner에서 개행 문자가 남는 버그 (BufferedReader에선 발생 안 함)
3

StringBuilder 출력 — System.out.println의 함정

System.out.println()을 반복문 안에서 호출하면 매번 flush가 발생합니다. 출력이 수만 줄이면 이것만으로 시간 초과가 날 수 있습니다.

느린 코드

for (int i = 0; i < 100000; i++) {
    System.out.println(arr[i]);
}
// 10만 번 flush → 시간 초과
VS

빠른 코드

StringBuilder sb = new StringBuilder();
for (int i = 0; i < 100000; i++) {
    sb.append(arr[i]).append('\n');
}
System.out.print(sb);
// 한 번만 flush → 통과
성능 차이가 얼마나 되나?
10만 줄 출력 기준:
• println 반복: ~800ms
• StringBuilder + 한 번 출력: ~50ms
→ 약 16배 차이

StringBuilder 핵심 메서드

Java
StringBuilder sb = new StringBuilder();

sb.append("hello");       // 문자열 추가
sb.append(42);             // 정수도 바로 추가 가능
sb.append('\n');           // 줄바꿈
sb.append(a).append(' ').append(b);  // 체이닝

System.out.print(sb);     // 마지막에 한 번만 출력

BufferedWriter로 출력하기 (대안)

Java
BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out));
for (int i = 0; i < N; i++) {
    bw.write(arr[i] + "\n");
}
bw.flush();  // 반드시 flush 호출!
bw.close();
💡
StringBuilder vs BufferedWriter
• StringBuilder: 간단하고 직관적, 대부분의 코테에서 충분
• BufferedWriter: 출력이 극단적으로 많을 때 (메모리에 다 담기 부담스러울 때)
• 실전에서는 StringBuilder가 정석 — 코드가 짧고 실수가 적음

int → long 오버플로우 감각

Java의 int는 약 21억(2,147,483,647)까지만 저장됩니다. 코딩 테스트에서 곱셈, 누적 합, 큰 수 연산이 나오면 반드시 long을 의심해야 합니다.

자료형 범위 대략적인 크기
int (32비트) -2,147,483,648 ~ 2,147,483,647 약 ±21억
long (64비트) -9.2 × 1018 ~ 9.2 × 1018 약 ±922경
오버플로우가 터지면 어떻게 되나?
Java에서 int 오버플로우는 에러 없이 조용히 음수로 뒤집어집니다.
2,147,483,647 + 1 = -2,147,483,648
틀린 답이 나오는데 원인을 못 찾아 시간을 날리는 최악의 패턴입니다.

위험 신호 체크리스트

이 조건이 보이면 long을 써라
// 1. N이 10만 이상이고 값이 10만 이상인 배열의 합
//    100,000 × 100,000 = 10,000,000,000 → int 범위 초과!

// 2. 두 int의 곱셈
//    50,000 × 50,000 = 2,500,000,000 → int 범위 초과!

// 3. 누적 합 (prefix sum)
//    원소가 최대 10^6이고 N이 10^5이면
//    합계 최대 = 10^11 → long 필수

// 4. 팩토리얼, 조합, 큰 수 모듈러 연산
//    중간 계산에서 long 범위도 넘을 수 있음

흔한 실수와 수정

버그 코드

int a = 100000;
int b = 100000;
int result = a * b;
// result = 1,410,065,408
// (오버플로우! 정답은 10^10)
VS

올바른 코드

int a = 100000;
int b = 100000;
long result = (long) a * b;
// result = 10,000,000,000
// 캐스팅은 곱셈 전에!
캐스팅 위치가 중요하다!
long result = a * b; → int끼리 먼저 곱해서 오버플로우 발생 후 long에 대입 (이미 늦음)
long result = (long) a * b; → a를 먼저 long으로 변환 후 곱셈 (안전)

빠른 판단 공식

문제에서 이 계산을 해보자
// 최대 입력값으로 계산했을 때:

// ① 합계: N × max_value
//   → 21억(2 × 10^9) 넘으면 long

// ② 곱: max_value × max_value
//   → 46,340 × 46,340 = 2,147,395,600 (int 거의 한계)
//   → 46,341부터는 int 오버플로우

// ③ "결과를 1,000,000,007로 나눈 나머지를 출력"
//   → 이 문구가 보이면 중간 곱셈에서 long 필수

// 요약: N > 5만 이거나 값 > 5만이면 습관적으로 long
💡
실전 습관
• 문제를 읽자마자 N과 값의 범위를 확인하고 int/long 결정
• 확신이 없으면 그냥 long을 써라 — 메모리 차이는 무시할 수준
• 배열 인덱스는 int로 충분 (배열 크기가 21억을 넘을 일은 없음)

실전 풀 템플릿

아래 템플릿을 복사해서 시작하면 입출력 세팅에 시간을 낭비하지 않습니다. 코테 시작 전에 이 구조를 손에 익혀두세요.

Java — 코딩 테스트 스타터 템플릿
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringBuilder sb = new StringBuilder();

        // ── 입력 ──
        int N = Integer.parseInt(br.readLine().trim());

        StringTokenizer st = new StringTokenizer(br.readLine());
        int[] arr = new int[N];
        for (int i = 0; i < N; i++) {
            arr[i] = Integer.parseInt(st.nextToken());
        }

        // ── 풀이 ──
        long answer = solve(N, arr);

        // ── 출력 ──
        sb.append(answer).append('\n');
        System.out.print(sb);
    }

    static long solve(int N, int[] arr) {
        // 여기에 풀이 작성
        return 0;
    }
}
템플릿 사용 요령
• import는 java.io.*, java.util.* 두 줄이면 충분
• throws IOException — try-catch 대신 main에 선언 (코드가 짧아짐)
• 풀이 로직은 별도 메서드로 분리하면 디버깅이 쉬움
• trim() — 백준 등에서 입력 끝에 공백이 붙는 경우 방지

2차원 배열 + 다중 출력 템플릿

Java — 확장 템플릿
public static void main(String[] args) throws IOException {
    BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    StringBuilder sb = new StringBuilder();

    int T = Integer.parseInt(br.readLine().trim());  // 테스트 케이스 수

    while (T-- > 0) {
        StringTokenizer st = new StringTokenizer(br.readLine());
        int N = Integer.parseInt(st.nextToken());
        int M = Integer.parseInt(st.nextToken());

        int[][] grid = new int[N][M];
        for (int i = 0; i < N; i++) {
            st = new StringTokenizer(br.readLine());
            for (int j = 0; j < M; j++) {
                grid[i][j] = Integer.parseInt(st.nextToken());
            }
        }

        sb.append(solve(N, M, grid)).append('\n');
    }
    System.out.print(sb);  // 모든 케이스 한 번에 출력
}
💡
3줄 요약
• 입력: BufferedReader + StringTokenizer (Scanner 금지)
• 출력: StringBuilder에 모아서 한 번에 print
• 자료형: N × value가 21억 넘을 것 같으면 long
