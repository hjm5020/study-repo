BFS (너비 우선 탐색)

가까운 노드부터 차례대로 탐색하는 알고리즘입니다. 큐(Queue)를 사용하며, 최단 거리를 구할 때 가장 먼저 떠올려야 하는 알고리즘입니다.

언제 쓰나?
• 최단 거리 / 최소 횟수를 구할 때
• 2차원 격자에서 영역 탐색 (미로, 섬 개수 등)
• 레벨 단위로 탐색이 필요할 때
BFS는 가까운 레벨부터 차례로 방문한다
Java — BFS 기본 템플릿
// 2차원 격자 BFS (최단 거리)
int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
boolean[][] visited = new boolean[N][M];

Queue<int[]> queue = new LinkedList<>();
queue.offer(new int[]{startR, startC});
visited[startR][startC] = true;
int dist = 0;

while (!queue.isEmpty()) {
    int size = queue.size();  // 현재 레벨의 노드 수
    for (int i = 0; i < size; i++) {
        int[] cur = queue.poll();
        if (cur[0] == endR && cur[1] == endC) return dist;

        for (int[] d : dirs) {
            int nr = cur[0] + d[0], nc = cur[1] + d[1];
            if (nr >= 0 && nr < N && nc >= 0 && nc < M
                && !visited[nr][nc] && grid[nr][nc] == 1) {
                visited[nr][nc] = true;
                queue.offer(new int[]{nr, nc});
            }
        }
    }
    dist++;
}
💡
핵심 포인트
• visited 체크는 큐에 넣을 때 해야 중복 방문을 막는다 (poll할 때 하면 중복 삽입됨)
• 최단 거리 = BFS의 레벨(depth)

DFS (깊이 우선 탐색)

한 방향으로 끝까지 파고든 뒤 되돌아오는 탐색입니다. 재귀 또는 스택으로 구현하며, 모든 경로를 탐색하거나 연결 요소를 찾을 때 사용합니다.

언제 쓰나?
• 모든 경우의 수 탐색 (백트래킹)
• 연결 요소 / 사이클 탐지
• 순열, 조합 생성
• 트리 순회 (전위/중위/후위)
DFS는 한 갈래를 끝까지 탐색한 뒤 되돌아온다

재귀 DFS

Java — 재귀 DFS
void dfs(int node, boolean[] visited, List<List<Integer>> graph) {
    visited[node] = true;
    // 현재 노드 처리

    for (int next : graph.get(node)) {
        if (!visited[next]) {
            dfs(next, visited, graph);
        }
    }
}

백트래킹 (조합 생성)

Java — N개 중 R개 조합
void combination(int[] arr, int start, List<Integer> path, int r) {
    if (path.size() == r) {
        result.add(new ArrayList<>(path));  // 복사!
        return;
    }
    for (int i = start; i < arr.length; i++) {
        path.add(arr[i]);
        combination(arr, i + 1, path, r);
        path.remove(path.size() - 1);  // 되돌리기
    }
}
💡
BFS vs DFS 선택 기준
• 최단 거리 → BFS (무조건)
• 모든 경로 탐색 / 백트래킹 → DFS
• 연결 요소 개수 → 둘 다 가능 (보통 DFS가 간결)

구현 (Simulation / Brute Force)

문제에서 시키는 대로 정확히 코드로 옮기는 유형입니다. 알고리즘 지식보다 꼼꼼한 구현력이 핵심이며, 코딩 테스트에서 가장 자주 출제됩니다.

구현 문제에서 자주 실수하는 부분
• 배열 인덱스 범위 (0-based vs 1-based)
• 방향 전환 (상하좌우, 회전)
• 경계 조건 (첫 번째, 마지막 원소)
• 자료형 범위 (int 오버플로우 → long 사용)
유형 설명 대표 문제
시뮬레이션 규칙대로 단계별 실행 삼성 기출 (뱀, 미세먼지, 톱니바퀴)
완전 탐색 모든 경우의 수를 다 해봄 N이 작을 때 (N ≤ 20)
문자열 처리 파싱, 변환, 패턴 매칭 카카오 기출 (압축, 매칭)
2차원 배열 격자 회전, 이동, 탐색 배열 90도 회전, 달팽이 채우기

배열 90도 회전 (시계 방향)

Java — N x N 배열 회전
int[][] rotate90(int[][] arr) {
    int n = arr.length;
    int[][] result = new int[n][n];
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            result[j][n - 1 - i] = arr[i][j];
        }
    }
    return result;
}

방향 전환 (dx, dy 패턴)

Java — 방향 벡터 활용
// 상, 우, 하, 좌 (시계방향)
int[] dx = {-1, 0, 1, 0};
int[] dy = {0, 1, 0, -1};
int dir = 0;  // 현재 방향 (0=상, 1=우, 2=하, 3=좌)

// 오른쪽 90도 회전
dir = (dir + 1) % 4;

// 왼쪽 90도 회전
dir = (dir + 3) % 4;  // = (dir - 1 + 4) % 4

// 다음 좌표
int nx = x + dx[dir];
int ny = y + dy[dir];
💡
구현 문제 접근법
• 문제를 작은 단계로 분해해서 각각 함수로 만들기
• 예제를 손으로 먼저 시뮬레이션한 뒤 코드 작성
• 매직 넘버 없이 상수를 명확히 정의

자료구조 (Stack, Queue, HashMap, Heap)

적절한 자료구조를 고르면 복잡한 문제가 단순해집니다. 코딩 테스트에서 가장 자주 쓰이는 4가지를 정리합니다.

자료구조 특징 시간복잡도 대표 활용
Stack LIFO (후입선출) push/pop O(1) 괄호 검증, 히스토리, 후위 표기식
Queue FIFO (선입선출) offer/poll O(1) BFS, 프로세스 스케줄링
HashMap Key-Value 쌍 get/put O(1) 평균 빈도 카운트, 중복 체크, Two Sum
PriorityQueue 항상 최소(최대)값 반환 offer/poll O(log N) 다익스트라, K번째 원소, 작업 스케줄링

Stack — 괄호 검증

Java — 올바른 괄호 문자열 판별
boolean isValid(String s) {
    Stack<Character> stack = new Stack<>();
    for (char c : s.toCharArray()) {
        if (c == '(') stack.push(c);
        else if (stack.isEmpty()) return false;
        else stack.pop();
    }
    return stack.isEmpty();
}

HashMap — 빈도 카운팅

Java — 배열에서 가장 많이 등장한 원소
Map<Integer, Integer> count = new HashMap<>();
for (int num : arr) {
    count.merge(num, 1, Integer::sum);
}
int maxKey = Collections.max(count.entrySet(),
    Map.Entry.comparingByValue()).getKey();

PriorityQueue — 최소 힙 활용

Java — K번째로 큰 원소
// 크기 K짜리 최소 힙을 유지하면 → 꼭대기가 K번째 최대값
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
for (int num : arr) {
    minHeap.offer(num);
    if (minHeap.size() > k) minHeap.poll();
}
return minHeap.peek();  // K번째 최대
💡
"어떤 자료구조?" 판단 기준
• 순서를 뒤집어야 한다 → Stack
• 먼저 들어온 것부터 처리 → Queue
• 빠른 검색 / 중복 체크 → HashMap, HashSet
• 최소/최대를 반복적으로 꺼낸다 → PriorityQueue

그리디 (Greedy)

매 순간 가장 좋아 보이는 선택을 하는 알고리즘입니다. "지금 최선 = 전체 최선"이 보장될 때만 사용 가능합니다.

그리디가 성립하는 조건
• 탐욕 선택 속성: 현재의 최적 선택이 이후 선택에 영향을 주지 않음
• 최적 부분 구조: 전체 문제의 최적해가 부분 문제의 최적해로 구성됨
→ 확실하지 않으면 반례부터 찾아보기
유형 전략 대표 문제
동전 거스름돈 큰 동전부터 사용 백준 11047
활동 선택 끝나는 시간이 빠른 순 회의실 배정 (백준 1931)
최소 개수 가능한 큰 단위부터 최소 신장 트리 (Kruskal)
정렬 후 선택 정렬 기준이 핵심 단어 정렬, 큰 수 만들기

예제 1: 동전 거스름돈

Java — 최소 동전 개수
int minCoins(int[] coins, int target) {
    Arrays.sort(coins);  // 오름차순 정렬
    int count = 0;
    for (int i = coins.length - 1; i >= 0; i--) {
        count += target / coins[i];
        target %= coins[i];
    }
    return count;
}
// 주의: 동전이 배수 관계가 아니면 그리디 불가 → DP 사용

예제 2: 회의실 배정

Java — 최대 회의 수
int maxMeetings(int[][] meetings) {
    // 끝나는 시간 기준 정렬 (같으면 시작 시간 기준)
    Arrays.sort(meetings, (a, b) ->
        a[1] != b[1] ? a[1] - b[1] : a[0] - b[0]);

    int count = 0, end = 0;
    for (int[] m : meetings) {
        if (m[0] >= end) {
            count++;
            end = m[1];
        }
    }
    return count;
}
💡
그리디 vs DP 구분법
• 그리디: "가장 ~ 한 것부터" 라는 직관이 통하고, 반례가 안 떠오르면 그리디
• DP: 현재 선택이 미래에 영향을 주면 DP (예: 배낭 문제)

DP (Dynamic Programming)

큰 문제를 작은 문제로 쪼개고, 결과를 저장해서 재사용하는 기법입니다. "이 문제를 더 작은 문제의 답으로 표현할 수 있는가?"가 DP의 본질입니다.

DP의 3단계
① 상태 정의: dp[i]가 무엇을 의미하는지 명확히 정의
② 점화식: dp[i]를 이전 상태들로 표현
③ 초기값: 가장 작은 문제의 답을 설정
유형 상태 정의 대표 문제
1차원 DP dp[i] = i번째까지의 최적값 피보나치, 계단 오르기, 타일링
2차원 DP dp[i][j] = i, j 조건에서의 최적값 배낭 문제, LCS, 편집 거리
LIS dp[i] = i번째까지의 최장 증가 부분수열 백준 11053, 11055
구간 DP dp[i][j] = 구간 [i, j]의 최적값 행렬 곱셈, 팰린드롬

예제 1: 계단 오르기 (1차원 DP)

Java — N번째 계단에 도달하는 방법 수
// 한 번에 1칸 또는 2칸 오를 수 있을 때
// 상태: dp[i] = i번째 계단에 도달하는 방법 수
// 점화식: dp[i] = dp[i-1] + dp[i-2]
// 초기값: dp[1] = 1, dp[2] = 2

int climbStairs(int n) {
    if (n <= 2) return n;
    int[] dp = new int[n + 1];
    dp[1] = 1;
    dp[2] = 2;
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}

예제 2: 0/1 배낭 문제 (2차원 DP)

Java — 무게 제한 W, 최대 가치
// 상태: dp[i][w] = i번째 물건까지 고려, 무게 w일 때 최대 가치
// 점화식: dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])

int knapsack(int[] weight, int[] value, int W) {
    int n = weight.length;
    int[][] dp = new int[n + 1][W + 1];

    for (int i = 1; i <= n; i++) {
        for (int w = 0; w <= W; w++) {
            dp[i][w] = dp[i - 1][w];  // 안 넣는 경우
            if (w >= weight[i - 1]) {
                dp[i][w] = Math.max(dp[i][w],
                    dp[i - 1][w - weight[i - 1]] + value[i - 1]);
            }
        }
    }
    return dp[n][W];
}

예제 3: LIS (최장 증가 부분수열)

Java — O(N log N) 이분 탐색 풀이
// dp 배열: 길이 i인 증가 부분수열의 마지막 원소 최솟값
int lis(int[] arr) {
    List<Integer> dp = new ArrayList<>();
    for (int num : arr) {
        int pos = Collections.binarySearch(dp, num);
        if (pos < 0) pos = -(pos + 1);
        if (pos == dp.size()) dp.add(num);
        else dp.set(pos, num);
    }
    return dp.size();
}
// 입력: [10, 20, 10, 30, 20, 50]
// 출력: 4 (10 → 20 → 30 → 50)
💡
DP 문제 접근 팁
• "~의 최대/최소", "~의 개수" 형태면 DP를 의심
• 점화식이 안 떠오르면 작은 예시(N=1,2,3)를 손으로 풀어보기
• 상태를 줄일 수 있으면 공간 최적화 (2D → 1D 롤링 배열)
