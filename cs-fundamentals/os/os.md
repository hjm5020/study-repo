# 운영체제

## 핵심 개념
> 운영체제는 하드웨어를 관리하고 응용 프로그램에 인터페이스를 제공하는 시스템 소프트웨어로, 프로세스/메모리/파일 시스템을 관리한다.

## 프로세스 vs 스레드

| | 프로세스 | 스레드 |
|---|---|---|
| 정의 | 실행 중인 프로그램 | 프로세스 내 실행 단위 |
| 메모리 | 독립적 (Code, Data, Heap, Stack) | Stack만 독립, 나머지 공유 |
| 통신 | IPC 필요 (파이프, 소켓, 공유 메모리) | 공유 메모리로 직접 통신 |
| 생성 비용 | 높음 | 낮음 |
| 영향 | 하나가 죽어도 다른 프로세스 영향 없음 | 하나가 죽으면 전체 프로세스 영향 |

```
프로세스 메모리 구조:
┌─────────┐ 높은 주소
│  Stack   │ ← 지역 변수, 함수 호출 (스레드마다 독립)
│    ↓     │
│          │
│    ↑     │
│   Heap   │ ← 동적 할당 (공유)
├─────────┤
│   Data   │ ← 전역/static 변수 (공유)
├─────────┤
│   Code   │ ← 실행 코드 (공유)
└─────────┘ 낮은 주소
```

## 프로세스 상태

```
         생성
          ↓
[New] → [Ready] ⇄ [Running] → [Terminated]
           ↑          ↓
           └── [Waiting/Blocked]
                  (I/O 대기)
```

## CPU 스케줄링

| 알고리즘 | 설명 | 특징 |
|----------|------|------|
| **FCFS** | 먼저 온 순서대로 | 간단, Convoy Effect |
| **SJF** | 실행 시간 짧은 것 우선 | 최적, 기아(Starvation) 문제 |
| **Round Robin** | 시간 할당량만큼 돌아가며 | 공평, 시분할 시스템 |
| **Priority** | 우선순위 높은 것 먼저 | 기아 → Aging으로 해결 |
| **Multilevel Queue** | 여러 큐, 각각 다른 알고리즘 | 실제 OS에서 사용 |

### Context Switch

```
프로세스/스레드 전환 시 현재 상태를 저장하고 다른 것의 상태를 복원

1. 현재 프로세스의 레지스터, PC 등을 PCB에 저장
2. 다음 프로세스의 PCB에서 상태 복원
3. 실행 재개

비용: 레지스터 저장/복원, 캐시 무효화, TLB 플러시
→ 스레드 전환이 프로세스 전환보다 가벼움 (메모리 공유)
```

## 동기화

### 경쟁 조건 (Race Condition)

```
여러 프로세스/스레드가 공유 자원에 동시 접근하여 결과가 실행 순서에 의존하는 상황
→ 상호 배제(Mutual Exclusion)로 해결
```

### 뮤텍스 (Mutex) vs 세마포어 (Semaphore)

| | Mutex | Semaphore |
|---|---|---|
| 값 | 0 또는 1 (이진) | 0 이상 (카운팅) |
| 소유권 | 락을 건 스레드만 해제 가능 | 누구나 signal 가능 |
| 용도 | 상호 배제 | 자원 카운팅, 동기화 |

### 데드락 (Deadlock)

```
4가지 조건이 모두 충족되면 발생:
1. 상호 배제 — 자원을 한 번에 하나의 프로세스만 사용
2. 점유 대기 — 자원을 점유한 채 다른 자원 대기
3. 비선점 — 다른 프로세스의 자원을 강제로 빼앗을 수 없음
4. 순환 대기 — 프로세스들이 원형으로 자원을 대기

해결:
- 예방: 4가지 조건 중 하나를 제거
- 회피: 은행원 알고리즘 (안전 상태 확인)
- 탐지 & 회복: 데드락 발생 후 감지하여 하나를 종료
```

## 메모리 관리

### 가상 메모리

```
물리 메모리보다 큰 프로그램을 실행할 수 있게 해주는 기법

프로세스 → 가상 주소 → [MMU/페이지 테이블] → 물리 주소

각 프로세스는 독립적인 가상 주소 공간을 가짐
실제로는 물리 메모리 + 디스크(스왑)를 합쳐 사용
```

### 페이징 (Paging)

```
가상 메모리를 고정 크기(보통 4KB)의 페이지로 분할
물리 메모리를 같은 크기의 프레임으로 분할
페이지 테이블로 매핑

장점: 외부 단편화 없음
단점: 내부 단편화 (페이지 내 남는 공간), 페이지 테이블 오버헤드
```

### 페이지 교체 알고리즘

| 알고리즘 | 설명 |
|----------|------|
| **FIFO** | 가장 오래된 페이지 교체 |
| **LRU** | 가장 오랫동안 사용되지 않은 페이지 교체 (가장 일반적) |
| **LFU** | 가장 적게 사용된 페이지 교체 |
| **Optimal** | 가장 오래 사용되지 않을 페이지 교체 (이론적 최적) |

### 스래싱 (Thrashing)

```
페이지 폴트가 과도하게 발생하여 실제 작업보다 페이지 교체에 더 많은 시간을 소비
→ CPU 이용률 급감

원인: 프로세스에 할당된 메모리 부족
해결: 워킹셋 모델, 프로세스 수 제한
```

## 면접 예상 질문

**Q: 프로세스와 스레드의 차이는?**
A: 프로세스는 독립적인 메모리 공간을 가진 실행 단위이고, 스레드는 프로세스 내에서 Stack만 독립적으로 가지고 나머지 메모리(Code, Data, Heap)를 공유하는 실행 단위이다. 스레드는 생성과 Context Switch 비용이 낮고 통신이 쉽지만, 동기화 문제가 발생할 수 있다.

**Q: Context Switch란?**
A: CPU가 하나의 프로세스/스레드에서 다른 것으로 전환할 때 현재 상태를 저장하고 새로운 상태를 복원하는 과정이다. 레지스터, PC 저장/복원과 캐시 무효화 등의 오버헤드가 발생한다.

**Q: 데드락의 발생 조건과 해결 방법은?**
A: 상호 배제, 점유 대기, 비선점, 순환 대기 4가지 조건이 모두 충족되면 발생한다. 예방(조건 제거), 회피(안전 상태 확인), 탐지 후 회복으로 해결할 수 있다.

**Q: 가상 메모리란?**
A: 각 프로세스에 독립적인 가상 주소 공간을 제공하여, 물리 메모리보다 큰 프로그램을 실행할 수 있게 하는 기법이다. 페이징을 통해 가상 주소를 물리 주소로 변환하며, 필요한 페이지만 물리 메모리에 올려 효율적으로 사용한다.
