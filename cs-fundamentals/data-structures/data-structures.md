# 자료구조

## 핵심 개념
> 자료구조는 데이터를 효율적으로 저장하고 접근하기 위한 구조로, 상황에 맞는 자료구조 선택이 성능을 결정한다.

## 시간 복잡도 요약

| 자료구조 | 접근 | 검색 | 삽입 | 삭제 |
|----------|------|------|------|------|
| **Array** | O(1) | O(n) | O(n) | O(n) |
| **LinkedList** | O(n) | O(n) | O(1)* | O(1)* |
| **Stack / Queue** | - | - | O(1) | O(1) |
| **HashMap** | - | O(1) | O(1) | O(1) |
| **TreeMap** | - | O(log n) | O(log n) | O(log n) |
| **Heap** | - | O(n) | O(log n) | O(log n) |

*노드 참조가 있는 경우

## 배열 (Array)

```
인덱스:  [0] [1] [2] [3] [4]
값:      10  20  30  40  50

- 연속된 메모리 공간
- 인덱스로 O(1) 접근
- 크기 고정 (Java에서 동적 배열 = ArrayList)
- 중간 삽입/삭제 시 요소 이동 필요 → O(n)
```

## 연결 리스트 (LinkedList)

```
[10|→] → [20|→] → [30|→] → [40|→] → null

단일 연결 리스트: 다음 노드만 참조
이중 연결 리스트: 이전/다음 노드 모두 참조 (Java의 LinkedList)

- 삽입/삭제 시 포인터만 변경 → O(1) (위치를 아는 경우)
- 인덱스 접근 불가 → 탐색 O(n)
- 캐시 지역성이 낮음
```

## 스택 (Stack)

```
LIFO (Last In First Out)

    push(30)    pop() → 30
      ↓           ↑
    [30] ← top   [20] ← top
    [20]          [10]
    [10]

활용:
- 함수 호출 스택
- 괄호 매칭
- 뒤로 가기 (Undo)
- DFS 구현
```

## 큐 (Queue)

```
FIFO (First In First Out)

    enqueue(40)                 dequeue() → 10
       ↓                           ↑
    [10] [20] [30] [40]         [20] [30] [40]
     ↑                    ↑
   front                 rear

활용:
- 작업 대기열 (메시지 큐)
- BFS 구현
- 캐시 (LRU의 기반)

변형:
- Deque: 양쪽 끝에서 삽입/삭제
- Priority Queue: 우선순위가 높은 것이 먼저 나옴 (Heap으로 구현)
- Circular Queue: 배열 기반, 포인터가 순환
```

## 해시 테이블 (Hash Table)

```
key → hashFunction(key) → 버킷 인덱스 → 값

[0] → null
[1] → ("apple", 100)
[2] → ("banana", 200) → ("cherry", 150)  ← 충돌 (체이닝)
[3] → null
[4] → ("date", 300)

충돌 해결:
1. 체이닝 (Chaining): 같은 버킷에 연결 리스트/트리
2. 개방 주소법 (Open Addressing): 다른 빈 버킷 탐색
   - 선형 탐사, 이차 탐사, 이중 해싱

Java HashMap:
- 체이닝 방식
- 버킷당 8개 이상 → Red-Black Tree로 변환
- Load Factor 0.75 → 리사이징
```

## 트리 (Tree)

### 이진 탐색 트리 (BST)

```
        8
       / \
      3   10
     / \    \
    1   6   14
       / \
      4   7

왼쪽 < 부모 < 오른쪽
검색/삽입/삭제: O(log n) (균형 시)
최악(편향): O(n) → 균형 트리(AVL, Red-Black)로 해결
```

### Red-Black Tree

```
- 자가 균형 이진 탐색 트리
- 각 노드에 빨간색/검은색 속성
- 삽입/삭제 시 회전으로 균형 유지
- O(log n) 보장
- Java의 TreeMap, TreeSet이 사용
```

### B-Tree / B+Tree

```
- 하나의 노드에 여러 키 저장 (다진 탐색 트리)
- 디스크 I/O 최소화 → 데이터베이스 인덱스에 사용
- B+Tree: Leaf 노드가 연결 리스트 → 범위 검색에 유리
- MySQL InnoDB 인덱스 = B+Tree
```

## 힙 (Heap)

```
최소 힙 (Min Heap):       최대 힙 (Max Heap):
       1                        9
      / \                      / \
     3   5                    7   8
    / \                      / \
   7   9                    3   5

- 완전 이진 트리
- 부모 ≤ 자식 (최소 힙) 또는 부모 ≥ 자식 (최대 힙)
- 삽입: O(log n), 최솟값/최댓값 추출: O(log n), 조회: O(1)
- Java의 PriorityQueue가 최소 힙으로 구현
```

## 그래프 (Graph)

```
인접 리스트:              인접 행렬:
0 → [1, 2]              0 1 2 3
1 → [0, 3]           0 [0 1 1 0]
2 → [0, 3]           1 [1 0 0 1]
3 → [1, 2]           2 [1 0 0 1]
                      3 [0 1 1 0]

인접 리스트: 공간 O(V+E), 간선 탐색 O(degree)
인접 행렬: 공간 O(V²), 간선 확인 O(1)
희소 그래프 → 인접 리스트, 밀집 그래프 → 인접 행렬
```

## 면접 예상 질문

**Q: Array와 LinkedList의 차이는?**
A: Array는 연속된 메모리에 저장되어 인덱스 접근이 O(1)이지만 삽입/삭제가 O(n)이다. LinkedList는 포인터로 연결되어 삽입/삭제가 O(1)이지만 접근이 O(n)이다. 캐시 지역성은 Array가 우수하다.

**Q: 해시 충돌이란 무엇이고 어떻게 해결하는가?**
A: 서로 다른 키가 같은 해시값(버킷)에 매핑되는 현상이다. 체이닝(같은 버킷에 연결 리스트)과 개방 주소법(다른 빈 버킷 탐색)으로 해결한다. Java HashMap은 체이닝을 사용하며, 충돌이 많으면 Red-Black Tree로 변환한다.

**Q: Stack과 Queue의 차이는?**
A: Stack은 LIFO(후입선출), Queue는 FIFO(선입선출)이다. Stack은 함수 호출, Undo에 사용되고, Queue는 작업 대기열, BFS에 사용된다.

**Q: B-Tree가 데이터베이스 인덱스에 사용되는 이유는?**
A: 하나의 노드에 여러 키를 저장하여 트리의 높이가 낮고, 디스크 I/O 횟수를 최소화한다. B+Tree는 Leaf 노드가 연결 리스트로 연결되어 범위 검색에도 효율적이다.
